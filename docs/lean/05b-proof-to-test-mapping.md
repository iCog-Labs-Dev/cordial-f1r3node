# 05b — Proof-to-test mapping

## Status and interpretation

Finality, approval, quorum, ratification, super-ratification, observation, and
equivocation have proved executable-to-Prop bridges. Ordering is independently
compared but **is not yet proved a refinement of KR4's opaque `tau`**.
Issue #188 is not fully PR-ready while this gap remains.

Every named theorem/lemma in the landed KR1–KR4 modules has one row below,
including private helpers and worked-example scaffolding. A Rust test exercises
a related concrete scenario; it does **not** prove Rust satisfies the theorem
universally. Proof-only helpers and missing direct coverage are explicit.
Definitions such as `Block.id_eq` and `ValidBlocklace.insert` are described in 05a.

The mapping is reviewed whenever Lean or Rust declarations move. The
conformance gate itself runs the Lean build/replay and parser/negative-test
suite; those tests validate executable behavior rather than merely checking
source-link locations.

## One row per theorem or lemma

Select a Rust test with
`cargo test -j 2 -p cordial-miners-core --test TEST_FILE TEST_NAME -- --exact`.
Trace fixtures are normal, equivocation, and low-stake; run parser/negative
tests with `cd lean && lake exe conformance_tests`.

## Executable soundness bridge

`CMRef.lean` proves `checkObserves_iff`, `checkEquivocation_iff`,
`checkApproves_iff`, `checkStrictTwoThirds_iff`, `checkRatifies_iff`,
`checkSuperRatifies_iff`, `checkFinal_iff`, and `buildWCert_invariant`.
The finality proof goes through the earlier `FinalLeader` predicate; it does
not mention Rust's decision. Replay reconstructs a proof-valid Blocklace,
loads external weights/leaders, checks evidence, and compares its own result.

Normal requires approval, certificate, positive finality, tau, and complete
output. Equivocation requires an independently validated fork and safe finality.
Low-stake requires approval evidence and negative weighted finality. These
non-vacuity checks supplement, not replace, semantic checking.

## Ordering and output: unresolved formal correspondence

Rust [`ordering::weighted_tau`](../../crates/cordial-miners-core/src/consensus/ordering.rs#L550) is compared with
`CMRef.computeTau`; [`test_ordering::weighted_tau_returns_xsort_of_approved_blocks_for_single_weighted_final_leader`](../../crates/cordial-miners-core/tests/test_ordering.rs#L675)
exercises single-leader ordering. [`ordering::xsort`](../../crates/cordial-miners-core/src/consensus/ordering.rs#L127)
is exercised by [`test_ordering::xsort_respects_predecessor_order`](../../crates/cordial-miners-core/tests/test_ordering.rs#L132)
and [`test_ordering::xsort_breaks_ties_by_block_identity`](../../crates/cordial-miners-core/tests/test_ordering.rs#L151).
`incorrect-tau` and `incorrect-output-prefix` are actual Lean negative tests.
Output events are emitted inside `weighted_tau`;
`emit_weighted_checkpoint_prefix` is a checkpoint-list helper, not the trace boundary.

There is **no proved `computeTau` ↔ `tau` bridge**. `Ordering.lean` exposes
an opaque function without a defining equation; `tau_prefix_monotone` is an
existing axiom, not a proved theorem. The signature does not identify the
external hash tie-break key or replay horizon used by the executable model.
Proved component predicates and negative order tests do not establish
correctness of their composition.

The prefix axiom alone is insufficient: an always-empty output and an
arbitrary constant singleton both satisfy prefix monotonicity. It cannot
determine which blocks belong in output, much less their canonical order.

Required prerequisite work: specify canonical leader recursion, approved-block
membership, topological ordering and tie-breaking; relate full output to a
bounded replay horizon; then prove executable refinement and prefix safety
under explicit protocol assumptions. Do not add an equivalence axiom or weaken
either model to hide this gap.

## Negative and mutation oracles

Exact Lean negative labels: `invalid-finality`, `insufficient-quorum`,
`invalid-certificate`, `duplicate-approver`, `duplicate-evidence`,
`false-equivocation`, `missing-predecessor`, `incorrect-tau`,
`incorrect-output-prefix`, `wrong-weight-table`,
`low-stake-false-finality`. Parser tests cover all 15 variants and rejection
of malformed/unknown/missing/mistyped/extra fields.

`scripts/issue188_mutation_test.sh` compiles the actual weakened Rust quorum
predicate, generates an execution, and requires unchanged Lean to reject its
insufficient-weight certificate. The oracle is independent of Rust's answer.
